## 一、项目整体结构说明

### 1.1 项目定位

`atguigu` 是一个**基于 LangGraph 的“文档导入 → 向量化 → 知识库检索问答”全流程系统**，用于把产品手册类 PDF/Markdown 文档解析成结构化切片、向量化后存入向量数据库（Milvus），并在用户提问时，通过多路检索（向量召回 + HyDE 假设文档召回 + 网络搜索）+ RRF 融合 + Cross-Encoder 重排，最终生成答案。

项目天然分成两大流水线（两个 LangGraph 状态图）：

| 流水线 | 入口图 | 作用 |
| --- | --- | --- |
| **导入流程（Import）** | `main_graph.ImportMainGraphRunner` | 接收 PDF/MD 文件 → 解析 → 切分 → 识别主体 → 向量化 → 写入 Milvus |
| **查询流程（Query）** | `query_process/nodes/main_graph.QueryMainGraphRunner` | 接收用户问题 → 识别主体 → 多路召回 → 融合重排 → 生成答案 |

还包含：配置层（`config`）、工具层（`tool`，封装 Milvus/MinIO/Mongo/BGE-M3/Rerank 等外部依赖）、Web 服务层（`web`，FastAPI 上传接口）、测试脚本层（`test`，早期手工验证脚本）。

### 1.3 两条流水线的节点编排（核心调用关系）

**导入流程 `ImportMainGraphRunner` 编排：**

```
entry ──(条件路由)──► [pdf 路径] node_pdf_to_md ──► node_md_img ──┐
   │                                                            ├─► node_document_split ─► node_item_name_recognition ─► node_bge_embedding ─► node_import_milvus ─► END
   └──(md 路径)──► node_md_img ──────────────────────────────────┘
```

- `node_entry` 根据后缀 `.pdf`/`.md` 设置 `is_pdf_read_enabled` / `is_md_read_enabled`，并路由到不同起点。
- PDF 路径：先 `node_pdf_to_md` 转 md，再进入 `node_md_img`（MD 路径则直接进入 `node_md_img`）。
- 后续固定链路：`md_img → document_split → item_name_recognition → bge_embedding → import_milvus → END`。

**查询流程 `QueryMainGraphRunner` 编排：**

```
node_item_name_confirm ──(条件路由)──► [answer 非空] node_answer_output ──► END
   │
   └──[answer 为空]──► 并行三路召回：
        ├─ node_search_embedding_hyde ─┐
        ├─ node_search_embedding ──────┼─► node_rrf ──► node_rerank ──► node_answer_output ──► END
        └─ node_web_search_mcp ────────┘
```

- 若 `node_item_name_confirm` 已直接给出答案（如“无法识别商品名”），则短路到 `node_answer_output`。
- 否则并行执行三路召回，三路结果汇聚到 `node_rrf`（这里实际做重排融合+断崖截断），再到 `node_rerank`（这里做经典 RRF 融合），最后 `node_answer_output` 生成答案。

> ⚠️ 注意：查询流程里 `node_rrf` 和 `node_rerank` 的命名与职责存在“错位”现象——`node_rrf` 实际做的是“rerank 重排 + 断崖截断”，`node_rerank` 实际做的是“经典 RRF 分数融合”。这与常见命名相反，文档中已分别按其真实代码逻辑说明。

### 3.1 `import_process/state.py`

**作用**：定义导入流程状态机的状态结构 `ImportGraphState`（TypedDict，即各节点之间流转的数据契约）。

```python
class ImportGraphState(TypedDict):
    task_id: str                       # 任务唯一ID，用于进度追踪（Web 上传时传入）
    is_md_read_enabled: bool           # 是否走 Markdown 读取路径（node_entry 设置）
    is_pdf_read_enabled: bool          # 是否走 PDF 解析路径（node_entry 设置）
    local_dir: str                     # 输出/工作目录（文件的父目录）
    local_file_path: str               # 原始输入文件路径
    file_title: str                    # 文件标题（文件名去后缀），多个节点共用
    pdf_path: str                      # PDF 路径（PDF 分支设置）
    md_path: str                       # Markdown 路径（解析/读取后设置）
    md_content: str                    # Markdown 全文内容
    chunks: list                       # 切片列表（核心载体，被多次扩充字段）
    item_name: str                     # 识别出的主体名（声明了但代码中主要由 chunks[].item_name 承载）
    embeddings_content: list           # 预留：含向量的列表，准备写入 Milvus
```
**关键变量含义**：`chunks` 是整个导入流程最核心的对象——它被 `node_document_split` 创建，被 `node_item_name_recognition` 追加 `item_name`，被 `node_bge_embedding` 追加 `dense_vector`/`sparse_vector`，最终被 `node_import_milvus` 写库。

### 3.2 `import_process/base.py`

**作用**：导入流程所有节点的抽象基类 `NodeBase`，统一“执行入口 + 日志 + 异常上报 + 进度追踪”逻辑。

```python
import time
from abc import ABC, abstractmethod
from atguigu.import_process.state import ImportGraphState
from atguigu.tool.logger import logger
from atguigu.tool.task_utils import add_running_task, add_done_task, add_node_duration

class NodeBase(ABC):
    name: str = "NodeBase"
    def __init__(self):
        # 强制子类必须定义 name（否则实例化就报错）
        if self.name == "NodeBase":
            raise ValueError(f'{self.__class__.__name__}请输入name属性')

    def __call__(self, state: ImportGraphState):
        # 节点统一执行入口（被图的 invoke 调用）
        task_id = state.get("task_id", "")
        start_time = time.time()
        try:
            logger.info(f'{self.name}开始执行')
            if task_id:                       # 有 task_id 才上报进度，避免命令行跑图污染内存态
                add_running_task(task_id, self.name)
            res = self.process(state)         # 子类实现真正逻辑
            logger.info(f'{self.name}执行完毕')
            if task_id:
                add_done_task(task_id, self.name)
                add_node_duration(task_id, self.name, time.time() - start_time)
            return res
        except Exception as e:
            logger.error(f'{self.name}执行失败，错误信息为：{e}')
            raise e                            # 向上抛，让 LangGraph 记录错误

    @abstractmethod
    def process(self, state: ImportGraphState):
        # 子类必须实现的业务方法
        pass
```
**关键设计**：
- `__call__` 包裹 `process`，自动记录“开始/完毕”、上报内存态进度（仅当有 `task_id`，即 Web 触发时）。
- 出错时统一打日志并 `raise`，错误信息会在 Web 端（如之前日志里的 `name 'state' is not defined`）体现。

### 3.3 `import_process/nodes/node_entry.py`

**作用**：导入流程入口节点。读取输入文件，按后缀判定走 PDF 还是 MD 路径，并初始化 state 中的分支标志与路径字段。

```python
class NodeEntry(NodeBase):
    name = "node_entry"
    def process(self, state):
        local_file_path = state.get("local_file_path", '')
        if not local_file_path:
            raise ValueError("未输入文件路径，请输入文件路径")
        local_file_path_obj = Path(local_file_path)
        if not local_file_path_obj.exists():
            raise FileNotFoundError("输入文件不存在")
        file_title = local_file_path_obj.stem      # 文件名去后缀，作为标题
        suffix = local_file_path_obj.suffix        # 文件后缀

        if suffix.lower() == ".pdf":
            state["is_pdf_read_enabled"] = True
            state["file_title"] = file_title
            state["pdf_path"] = str(local_file_path_obj)
            state["local_dir"] = str(local_file_path_obj.parent)  # 输出目录=输入文件所在目录
            return state
        elif suffix.lower() == ".md":
            state["is_md_read_enabled"] = True
            state["file_title"] = file_title
            state["md_path"] = str(local_file_path_obj)
            state["local_dir"] = str(local_file_path_obj.parent)
            return state
        else:
            raise ValueError(f"输入文件格式错误{suffix}")
```
**关键变量**：`file_title` 是后续一切文件名、Milvus 过滤、落盘目录的基础；`local_dir` 在后续 `node_item_name_recognition` / `node_import_milvus` 被用来拼接输出目录。

### 3.4 `import_process/nodes/node_pdf_to_md.py`

**作用**：把 PDF 上传到 Mineru 云服务解析，轮询拿到结果 zip 下载链接，下载并解压为 Markdown（重命名 `full.md` 为 `<stem>.md`）。

**核心方法解析：**

- `check_pdf(state)`：校验 `pdf_path` / `local_dir`，返回 `pdf_path, pdf_path_obj, load_path_obj`。`local_dir` 缺省时回退到 `local_file_path` 的父目录。
- `up_pdf(pdf_path_obj, load_path_obj)`：调用 Mineru 的 `/api/v4/file-urls/batch` 拿到上传 URL，把 PDF 内容 `PUT` 上去，返回 `batch_id`。
- `get_md_zip_url(batch_id)`：轮询 `/api/v4/extract-results/batch/{batch_id}`，最多 120 秒，直到 `state == "done"`，返回 `full_zip_url`。
- `download_pdf(md_zip_url, local_dir_obj, pdf_path_obj)`：下载 zip → 解压到 `<local_dir>/<stem>/` → 把 `full.md` 重命名为 `<stem>.md` → 读全文返回 `(md_content, new_md_path_obj)`。
- `process(state)`：串联以上步骤，返回 `{"md_path": ..., "md_content": ...}`。

```python
class ImportMainGraphRunner:
    def __init__(self):
        self.builder = StateGraph(state_schema=ImportGraphState)
        self.add_node()
        self.add_edge()
        self.graph = None

    def add_node(self):
        # 注册 7 个节点（以 node.name 为节点 id）
        self.builder.add_node(NodeEntry.name, NodeEntry())
        self.builder.add_node(NodeMDImg.name, NodeMDImg())
        self.builder.add_node(NodePDFToMD.name, NodePDFToMD())

        self.builder.add_node(NodeBGEEmbedding.name, NodeBGEEmbedding())
        self.builder.add_node(NodeImportMilvus.name, NodeImportMilvus())

    def after_entry_router(self, state):
        # 条件路由：根据 node_entry 设置的分支标志决定起点
        md_bool = state.get("is_md_read_enabled", False)
        pdf_bool = state.get("is_pdf_read_enabled", False)
        if md_bool:   return NodeMDImg.name
        elif pdf_bool: return NodePDFToMD.name
        else:         return END

    def add_edge(self):
        self.builder.set_entry_point(NodeEntry.name)
        self.builder.add_conditional_edges(NodeEntry.name, self.after_entry_router)
        self.builder.add_edge(NodePDFToMD.name, NodeMDImg.name)
        self.builder.add_edge(NodeMDImg.name, NodeDocumentSplit.name)
        self.builder.add_edge(NodeDocumentSplit.name, NodeItemNameRecognition.name)
        self.builder.add_edge(NodeItemNameRecognition.name, NodeBGEEmbedding.name)
        self.builder.add_edge(NodeBGEEmbedding.name, NodeImportMilvus.name)
        self.builder.add_edge(NodeImportMilvus.name, END)

    def garph_invoke(self, state):          # 注意方法名拼写 garph（原文如此）
        self.graph = self.builder.compile()
        return self.graph.invoke(state)

    @classmethod
    def create_run(cls, state):
        return cls().garph_invoke(state)    # 供 Web 层调用
```
**关键说明**：`create_run` 是 Web 上传接口的入口；图的执行是**同步阻塞**的（`graph.invoke`），在 `import_service.py` 的后台任务中运行。

### 5.3 `query_process/nodes/node_item_name_confirm.py` ⭐（生效版）

**关键变量**：`score` 阈值（0.85 / 0.6）控制“确认 / 反问 / 放弃”三态；`final_item_names` 为空且 `answer` 非空时，主图会短路到答案输出。

### 5.5 `query_process/nodes/node_search_embedding.py`

**作用**：普通向量召回。用 `rewritten_query` 向量化后在 `chunks_collection` 做混合检索，并用 `item_name in [...]` 表达式限定只搜该商品名下的切片。

```python
def process(self, state):
    rewritten_query = state.get("rewritten_query", "")
    item_names = state.get('item_names')
    if not rewritten_query: raise ValueError("用户问题为空...")
    if not item_names:      raise ValueError("主体名为空...")
    embeddings = get_bge_m3_embedding([rewritten_query])
    dense_data = embeddings['dense'][0]; sparse_data = embeddings['sparse'][0]
    # 转义 item_names，构造 Milvus 布尔表达式
    item_names = [iname.replace('\\','\\\\').replace('"','\\"').replace("'","\\'") for iname in item_names]
    expr = f"item_name in {json.dumps(item_names)}"
    reqs = create_reqs(dense_data=dense_data, sparse_data=sparse_data,
                       dense_anns_field="dense_vector", sparse_anns_field="sparse_vector",
                       limit=10, expr=expr)
    res = search_hybrid(collection_name=MilvusConfig.chunks_collection, reqs=reqs,
                        ranker=(0.8, 0.2), limit=10,
                        output_fields=["id","file_title","title","content","item_name"])
    chunks = [ {**item["entity"], "score": item["distance"], "source": "local"} for item in res[0] ]
    return chunks   # 注意：直接返回 list（LangGraph 会把 list 当作整体更新，下游接力使用）
```
**关键变量**：`expr` 用 `item_name in [...]` 实现“按商品名过滤”，保证只召回目标商品的文档；`source="local"` 标记来源（区别于 web）。

```python
    dense_data = embeddings["dense"][0]; sparse_data = embeddings["sparse"][0]
    # 同样按 item_name 过滤
    reqs = create_reqs(dense_data=dense_data, sparse_data=sparse_data,
                       expr=f'item_name in {json.dumps(item_names)}', limit=10)
    res = search_hybrid(reqs=reqs, collection_name=MilvusConfig.chunks_collection,
                        ranker=(0.8,0.2), limit=10,
                        output_fields=["id","file_title","title","content","item_name"])
    return [{**r["entity"], "score": r["distance"], 'source':'local'} for r in res[0]]
```
**关键变量**：`merge_query` 是 HyDE 的核心——用“伪造答案”的语义去检索，对短问题/口语化问题召回更友好。

### 5.8 `query_process/nodes/node_rrf.py` ⭐（实际做“重排+断崖截断”）

**作用**：按命名是“RRF 融合”，但**实际代码**是把 `rrf_chunks`（三路召回合并）+ `web_search_docs` 统一格式后，调用 Cross-Encoder `rerank` 重排，再做**动态 Top-K 断崖截断**，返回最终候选文档。

```python
def process(self, state):
    rewritten_query = state.get("rewritten_query", "")
    rrf_chunks = state.get("rrf_chunks", '')      # 这里 rrf_chunks 实际是“三路合并后的文档”
    web_search_docs = state.get("web_search_docs", '')
    # 校验非空
    merged_docs = rrf_chunks + web_search_docs
    merged_docs = [{'title': d.get('item_name','title'), 'content': d.get('content',''),
                    'url': d.get('url',''), 'source': d.get('source','')} for d in merged_docs]
    texts = [d['content'] for d in merged_docs]
    res = rerank(texts=texts, query=rewritten_query, limit=len(merged_docs))  # Cross-Encoder 打分
    for r in res:
        merged_docs[r['index']]['score'] = r['score']        # 用重排分数覆盖
    rrf_docs = sorted(merged_docs, key=lambda x: x['score'], reverse=True)

    # 动态 TopK 断崖截断
    RERANK_MAX_TOPK = 10; RERANK_MIN_TOPK = 3
    RERANK_GAP_RATIO = 0.20; RERANK_GAP_ABS = 0.10
    max_topk = min(RERANK_MAX_TOPK, len(rrf_docs))
    min_topk = min(RERANK_MIN_TOPK, max_topk)
    for i in range(min_topk-1, max_topk-1):
        gap = rrf_docs[i]['score'] - rrf_docs[i+1]['score']
        if gap > RERANK_GAP_RATIO or gap > RERANK_GAP_ABS:   # 分数断崖 → 截断
            rrf_docs = rrf_docs[:i+1]
            break
    # ⚠️ 注意：函数没有 return！（见下方问题清单）
```
**关键变量**：4 个阈值控制“最多 10、最少 3、相邻分差超 0.20 或 0.10 即截断”，目的是在相关性与覆盖率间平衡。

> ⚠️ **Bug**：`node_rrf.process` 末尾**没有 `return rrf_docs`**，且它消费了 `rrf_chunks`/`web_search_docs` 但查询主图并没有把“三路合并”结果写进 `state["rrf_chunks"]`（三路召回各自返回 list，LangGraph 会把 list 直接覆盖式更新 state，并不会自动 `rrf_chunks = embedding+hyde+web`）。因此该节点按当前编排**无法正确拿到输入**。详见文末“遗留问题清单”。

### 5.9 `query_process/nodes/node_rerank.py` ⭐（实际做“经典 RRF 融合”）

**作用**：按命名是“重排”，但**实际代码**是经典 **Reciprocal Rank Fusion**：把 `embedding_chunks`（权重 2）与 `hyde_embedding_chunks`（权重 1）两路结果按排名做 RRF 分数融合（k=60），合并同 id 的文档并加权求和，按总分排序返回。

```python
def process(self, state):
    embedding_chunks = state.get("embedding_chunks")
    hyde_embedding_chunks = state.get("hyde_embedding_chunks")
    weights = [(embedding_chunks, 2), (hyde_embedding_chunks, 1)]
    rrf_after_chunks = {}
    k = 60
    for chunks, weight in weights:
        for idx, chunk in enumerate(chunks, start=1):
            new_score = chunk.get('score') + weight/(idx + k)   # RRF 公式：原 score + 权重/(排名+k)
            new_id = chunk.get('id')
            if new_id in rrf_after_chunks:
                rrf_after_chunks[new_id]['score'] += new_score  # 同 id 累加
            else:
                chunk['score'] = new_score
                rrf_after_chunks[new_id] = chunk
    rrf_chunks = sorted(rrf_after_chunks.values(), key=lambda x: x['score'], reverse=True)
    return rrf_chunks
```
**关键变量**：`k=60` 是 RRF 标准平滑常数；权重 `(2, 1)` 表示普通向量召回比 HyDE 更重要；`new_id` 即 Milvus 主键，用于跨路去重合并。

> ⚠️ 注意：这里的两个 `state` 字段 `embedding_chunks` / `hyde_embedding_chunks` 正是 `node_search_embedding` 与 `node_search_embedding_hyde` 直接 `return list` 后由 LangGraph 写入的。`node_rerank` 只融合这两路，**没有纳入 `web_search_docs`**（web 文档无 `id` 字段，难以 RRF 合并）。

```python
async def get_task_status(task_id: str):
    return get_task_info(task_id)                            # 返回进度/状态/耗时

if __name__ == '__main__':
    import uvicorn
    uvicorn.run(app, host="localhost", port=8000)
```
**关键变量/设计**：
- `task_id` 贯穿上传→后台导入→进度查询，是前端轮询的钥匙。
- `/upload` 立即返回 `task_id`，真正的重活（PDF 解析、向量化等）放在 `BackgroundTasks` 后台执行，避免 HTTP 超时。
- `local_dir = d:\output\YYYYMMDD` 与导入节点里 `local_dir` 语义一致，最终产物落在 `d:\output\YYYYMMDD\<file_title>\`。
- 注意：`web/page/` 目录为空（无前端页面），目前只有后端接口。

## 十、遗留问题 / 待修复清单（重要）

1. **⚠️ `query_process/nodes/main_graph.py` 导入缺失模块**：第 12 行 `from atguigu.tool.json_format_tool import json_format` 引用的文件 **不存在**（`tool/` 下无 `json_format_tool.py`），运行查询主图会 `ModuleNotFoundError`。建议：要么新建 `tool/json_format_tool.py` 提供 `json_format`，要么把导入改为 `from atguigu.tool.json_tool import json_tool`。
