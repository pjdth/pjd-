## 一、项目定位

`atguigu` 是一个基于 **LangGraph** 的 **「文档导入 → 向量化 → 混合检索 → 流式问答」全流程系统**。原始场景是产品手册知识库（烫金机），现已迁移为 **小说/听书知识库**：导入小说 MD 文件，建立书籍元数据 + 向量知识库，支持知识问答、书籍推荐、书籍详情，以及书库浏览、阅读（翻页/目录/进度记忆）和文字转语音（含上传 mp3 声音复刻）。

技术栈：Python + FastAPI + LangGraph + LangChain + Milvus（dense+sparse 混合检索）+ BGE-M3 + MongoDB + MinIO + edge-tts + 阿里云 DashScope（LLM / rerank / 声音复刻）+ SSE 流式。

项目天然分成两大 LangGraph 流水线 + 三个独立 Web 服务：

| 层 | 内容 |
| --- | --- |
| **导入流水线** | `import_process/main_graph.ImportMainGraphRunner`：MD → 元数据解析 → 切分 → 主体识别 → 向量化 → 写 Milvus |
| **查询流水线** | `query_process/nodes/main_graph.QueryMainGraphRunner`：意图分流 → 主体确认 → 三路召回 → RRF 融合 → 重排 → 流式答案 |
| **Web 服务** | `import_service`(8000 上传) / `query_service`(8001 SSE 问答) / `library_service`(8002 书库+TTS) |
| **前端页面** | `web/page/`：`chat.html`（问答）、`import.html`（导入）、`library.html`（书库阅读器）——统一赛博朋克风格 |

## 三、导入流水线（ImportMainGraphRunner）

链路：`node_entry → node_md_img → node_document_split → node_item_name_recognition → node_bge_embedding → node_import_milvus → END`（PDF 经 `node_pdf_to_md` 转 MD 后并入）。

### 各节点职责

| 节点 | 关键逻辑 |
| --- | --- |
| **node_entry** | 判断文件扩展名（pdf/md），写 state 分支标志。 |
| **node_pdf_to_md** | 调 Mineru API 把 PDF 转成 Markdown，保存本地。 |
| **node_md_img** | 提取 md 中图片 → VLM 生成文字摘要 → 图片上传 MinIO → 把 md 里图片标记改写为「图片+摘要」。 |
| **node_document_split** | ① `parse_book_metadata`：解析 `## 元数据` 区（书名/作者名/条目名称/类别标签）+ 正则提取"时长约 X 小时"；② `map_content_type`：按标题映射 7 种内容类型（有声书信息/书籍简介/作者介绍/听书笔记/推荐运营资料/用户评论摘要/常见问答）；③ 标题粗切（`' '.join` 连接，已修 `/n` bug）+ RecursiveCharacterTextSplitter 细切；④ 出口 `_clean_text` 统一清理 content/title（真换行/字面 \n//n → 单空格）。 |
| **node_item_name_recognition** | LLM 从切片识别主体名（小说名，含作者）；**空串兜底** `未识别内容`（防止空 item_name 写 Milvus 报错）；写 `item_name` 集合（建表走锁+等索引）；把 item_name 回填每个 chunk。 |
| **node_bge_embedding** | BGE-M3 为 chunk 生成 dense(1024) + sparse 向量（双锁保护，见下）。 |
| **node_import_milvus** | 建 chunks 集合（schema：id/item_name/book_name/file_title/content/title/part/author/entry_name/category/content_type/duration/dense/sparse）+ 等索引就绪 + 插入。 |

### 关键机制
- **建表并发安全**：`_ensure_collection_ready` 用模块级 `threading.Lock` 串行化「检查→建表→等索引 Finished」，集合已存在时用 `list_indexes` 兜底补建缺失索引。
- **主体名兜底**：模型返回空串一律替换为 `未识别内容`。

## 四、查询流水线（QueryMainGraphRunner）

入口先做**意图分流**，再走不同子链路：

```
node_query_intent
  ├─ recommend → node_recommend → node_answer_output
  ├─ detail    → node_detail    → node_answer_output
  └─ qa        → node_item_name_confirm → 三路召回 → node_rrf → node_rerank → node_answer_output
```

### 各节点职责

| 节点 | 关键逻辑 |
| --- | --- |
| **node_query_intent** | 规则优先（推荐关键词→recommend；书名号+详情词→detail），拿不准走 LLM；LLM 失败降级 qa 保链路不断。 |
| **node_item_name_confirm** | 把历史 10 条 + 当前问题拼成上下文 → LLM 抽取 `item_names` 与 `rewritten_query`（多轮指代消解）→ 逐个向量化在 Milvus item_name 表混合检索 → 按分数对齐：≥0.85 确认、0.6~0.85 列候选让用户选、否则提示无法识别；同时维护 Mongo 历史（含 image_urls）。 |
| **node_search_embedding** | 用 rewritten_query 的向量在 chunks 表 hybrid_search（dense+sparse，WeightedRanker 0.8/0.2），透传元数据字段。 |
| **node_search_embedding_hyde** | HyDE：先让 LLM 生成"假设答案"再向量检索，提升召回。 |
| **node_web_search_mcp** | 经 DashScope WebSearch MCP 联网检索补充。 |
| **node_rrf** | 对 embedding/hyde 两路结果做 RRF 融合（`1/(k+rank)` 打分合并）。 |
| **node_rerank** | `get_merge_chunks` 合并本地 RRF 结果 + web 文档，归一化字段，**过滤空内容**（空串/纯空白/None，保证 rerank 返回 index 与文档对齐）；`get_rerank_chunks` 调 `qwen3-vl-rerank` 重排并回写 score、倒序排序；空列表时跳过 API 直接返回。 |
| **node_recommend** | 按场景（类别/作者/标签）混合检索 → 按书名聚合 → `RECOMMEND_PROMPT` 生成结构化推荐（列表+特色+适合人群+推荐理由）；知识库为空时友好提示。 |
| **node_detail** | 检索 → 取主书 15 个切片 → `DETAIL_PROMPT` 生成结构化详情（简介/作者/时长/标签/亮点/FAQ）。 |
| **node_answer_output** | 组装上下文（片段+来源+分数）→ `ANSWER_PROMPT` 流式生成答案（含【图片】区块、【参考来源】清单）→ 正则抽取图片 URL 存历史 → `add_or_update_history` 落库 → SSE 推 delta/final。 |

### SSE 流式机制（query_service）
- `POST /query`：生成 `task_id` → `create_queue(task_id)` → 后台线程跑查询图 → 立即返回 task_id。
- 后台 `run_main_graph` 是**生产者**：节点用 `put_data(task_id, "progress"/"delta"/"final"/"error", data)` 往 `queue_dict[task_id]`（内存 `queue.Queue`）塞数据。
- `GET /stream/{task_id}`：`StreamingResponse(generate_stream(...), media_type="text/event-stream")` 是**消费者**：阻塞 `get_data` 取数据，按 SSE 协议 `event: xxx\ndata: json\n\n` 下发，遇终态（completed/failed/error）断开。
- 前端 `chat.html` 用 `EventSource('/stream/'+task_id)` 监听 progress/delta/final/error 事件。
- 异常兜底：`_friendly_error_message` 把 collection not found/网络/Milvus 错误转成人话，不再裸抛 500。

## 七、关键设计点与踩坑记录（为什么这么写）

1. **SSE = 后台任务 + 按 task_id 隔离的内存队列**：`POST /query` 不阻塞返回 task_id，后台线程跑图、把进度/增量塞 `queue.Queue`，`/stream` 生成器阻塞取数按 SSE 协议下发——"算的人"和"发的人"解耦。⚠️ 内存队列只能单进程，上线多 worker 需换 Redis。
2. **Milvus 建表并发竞态**：多文件同时导入会重复建表 + 索引未就绪就 load 报 `no vector index`。修复：进程内锁串行化「检查+建表+等索引 Finished」，已存在则补建缺失索引。
3. **BGE-M3 加载/推理竞态**：多线程首调并发 from_pretrained 报 meta tensor 错误；加「加载锁」后 11 线程同时 encode 又触发 Windows 原生段错误（0xC0000005）。修复：**加载锁 + 推理锁双锁**，GPU 模型同一时刻只允许一个线程使用。
4. **rerank 空内容**：网络 snippet / 本地切片可能为空，DashScope 拒绝空文档。修复：拼装阶段过滤空内容（保证 index 对齐）+ 空列表跳过 + 入参校验。
5. **商品→小说域迁移**：只改 `prompt.py` 文案（导入侧/查询侧/回答标签），字段名 `item_name`、检索/RRF/rerank/SSE 逻辑全部不动。
6. **声音复刻**：CosyVoice 老接口必须公网 URL（内网不可用），改走 `qwen-voice-enrollment` **base64 直传**；`preferred_name` 只允许字母/数字/下划线，中文名需清洗（`re.sub` 后兜底时间戳）。
7. **/n 字面 bug**：`node_document_split` 用 `'/n'.join` 连接行导致书库全是 `/n`，已改为空格连接 + 导入/展示双层清理。
8. **元数据 + 意图分流**：导入侧解析书名/作者/类别/时长入库；查询侧 `node_query_intent` 把 recommend/detail/qa 分到不同子链路，统一走 `/query` + SSE，前端无感。

## 九、启动与使用

```bash
# 三个服务（各自终端）
D:\code\uv1\.venv\Scripts\python.exe D:\code\uv1\atguigu\web\api\import_service.py   # 8000
D:\code\uv1\.venv\Scripts\python.exe D:\code\uv1\atguigu\web\api\query_service.py    # 8001
D:\code\uv1\.venv\Scripts\python.exe D:\code\uv1\atguigu\web\api\library_service.py  # 8002
```

- 导入：`import.html` 上传小说 MD → 自动建表、写 Milvus、登记书库。
- 问答/推荐/详情：`chat.html`（`有哪些科幻类有声书？` / `《三体》讲了什么？` / `活着适合什么人听？`）。
- 书库/阅读/听书：`library.html`（打开书籍 → 翻页阅读 → 朗读/调速/上传自己的声音）。

依赖外部服务：Milvus、MongoDB、MinIO（内网）；DashScope（LLM/rerank/声音复刻，需 API Key）；edge-tts（微软，需外网）。
